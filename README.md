# APRON 07

机场机坪保障指挥模拟。玩家为不同机型编辑版本化的地面保障流程，在并行效率与现场资源之间取舍，并处理已开工航班的流程迁移。

## 安装与运行

```sh
npm install
npm run dev      # 本地开发
npm test         # 逻辑 / 存档 / 排程 / SSR 冒烟测试
npm run build    # 类型检查 + 生产构建
```

Docker 方式：

```sh
docker compose up --build
```

浏览器打开 http://localhost:8120 。

## 保障流程模型

- 流程按机型（窄体 / 宽体）分为两个模板，每个模板维护一串**不可变的已发布版本**。
- 航班停靠分配机位的瞬间**钉住**当时的最新版本；此后模板再发布新版本，不影响已经开工的航班。
- 每个流程版本包含若干步骤（`WorkflowStep`）：
  - `kind`：作业类型（行李、加油、清洁、餐食、电源、清水、除防冰）
  - `copies`：重复作业数量，例如宽体机需要两辆行李车
  - `prereqs`：有条件前置，`all` 要求该步骤全部副本完成，`any` 要求至少一个副本完成
  - `mode`：尽量并行 / 全部串行；`maxConcurrent` 是机位现场服务位的安全上限
- 作业目录 `jobCatalog` 声明每种作业所需车辆、基准时长与**安全互斥关系**
  （例如加油与除防冰禁止同时作业）。

## 流程编辑器

顶栏流程图图标打开编辑器：

- 新增 / 删除作业、调整重复副本数量、切换前置关系与 all/any 条件。
- 前置依赖按 DAG 校验，环形依赖、悬空引用、自环都会被阻断并高亮环上的步骤。
- 右侧"What-If"面板用事件驱动排程模拟，对比并行 / 串行的预计完成时间、
  服务位峰值占用与车辆需求；车辆不足会明确标记。
- 发布生成新版本，默认用于所有尚未开工的航班。

## 已开工航班的迁移

已停靠航班继续使用钉住的旧版本，玩家可在航班面板显式迁移。迁移计划器
（`features/workflow/lib/migration.ts`）**只按稳定的 `stepId` 对齐**，
名称相同但标识不同的步骤按"新增 + 移除"处理，绝不凭名字继承成果：

- 已完成成果：按 stepId 继承；新流程删除的步骤成果标记为 `legacy` 保留备查，不参与离港检查。
- 在途车辆：随车保留，新增前置不追溯已开工副本；若新流程删除了车辆正在执行的步骤，
  迁移被阻断，对话框指出具体车辆，现场保持不变。
- 未派遣副本：保留并适用新前置；新增前置未满足时会提示等待关系。
- 新增副本：按新版本创建为待派遣任务。

## 离港与存档

- 离港检查按该航班实际钉住的流程版本判断，每个步骤的每个副本都必须完成。
- 存档为 v2（`apron07-shift-v2`），每项作业都带 `flowId / flowVersion / stepId`，
  恢复后仍归属正确版本；严格校验器会验证版本存在性、副本数量、前置 DAG、
  服务位上限与安全互斥。
- 旧 v1 存档（`apron07-shift-v1`）读取时显式升级：旧作业以 `stepId = kind` 映射，
  无法识别的作业类型直接丢弃。

## 目录结构

```
src/features/workflow/   # 作业目录、DAG 校验、排程估算、迁移计划、编辑器
src/features/services/   # 基于版本步骤的派遣与作业推进
src/features/flights/    # 航班指令、按实际流程的离港检查
src/features/fleet/      # 七类作业车辆
src/features/session/    # 时钟、v2 存档与校验、v1 升级
scripts/                 # 冒烟测试与 SSR 渲染检查
```
